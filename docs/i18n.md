# Localisation

Mire est traduisible depuis la tâche P1-28. Le français et l'anglais sont intégrés (décision D-11) ; les autres
langues viendront par des packs de langue (addons de données, P3-29), au même format que les catalogues intégrés.

- Moteur, formats et choix de la langue : `@mire/shared/i18n` (`packages/shared/src/i18n/`).
- Catalogues intégrés : `packages/shared/src/i18n/locales/fr.json` et `en.json`.
- Langue de l'interface dans le processus principal : `src/main/i18n/`.

Les textes du processus principal sont dans les catalogues depuis P1-29 ; ceux de l'interface y passeront pendant
la phase 2.

## Règle

Tout nouveau texte destiné à l'utilisateur passe par les catalogues et est fourni en français **et** en anglais,
dans la même PR. `npm run i18n:check` (lancé par la CI) le vérifie.

## Contrat d'un catalogue

Un fichier JSON par langue, nommé d'après le code de la langue (`fr.json`, `en.json`, `pt-BR.json`) :

```json
{
  "meta": {
    "code": "fr",
    "name": "Français",
    "app": "1.0.0"
  },
  "messages": {
    "library": {
      "errors": {
        "folderNotFound": "Dossier introuvable : {path}"
      },
      "fileCount": {
        "one": "{count} fichier",
        "other": "{count} fichiers"
      }
    }
  }
}
```

| Champ | Contenu |
| --- | --- |
| `meta.code` | Code BCP 47 de la langue ; identique au nom du fichier. |
| `meta.name` | Nom de la langue **dans cette langue** (`Français`, `English`, `Deutsch`), tel que l'affichera le sélecteur. |
| `meta.app` | Version de Mire dont le catalogue couvre les textes. Un pack plus ancien que l'application peut manquer de clés : elles viennent alors de l'anglais, puis du français. |
| `messages` | Arbre des textes. Une feuille est un texte (chaîne) ou un pluriel (objet de formes). |

Les packs de langue (P3-29) reprendront ce format tel quel ; leur manifeste d'addon s'ajoutera autour.

## Clés

- Hiérarchiques, par domaine puis par sujet : `library.errors.folderNotFound`, `downloads.state.paused`,
  `settings.language.label`. Le premier niveau est le domaine du code (`library`, `games`, `tv`, `web`,
  `downloads`, `store`, `settings`…) ; `common` regroupe les mots partagés (`OK`, `Annuler`, `Fermer`).
- En anglais et en `camelCase`, sans espace ni point dans un segment.
- Une clé désigne un sens, pas un texte : deux textes identiques aujourd'hui mais de sens différent ont deux clés.
- Les noms `zero`, `one`, `two`, `few`, `many` et `other` sont réservés aux formes du pluriel : un groupe de clés
  ne les emploie pas.
- Une clé ne se renomme pas à la légère : les packs de langue la reprennent.

## Variables

`{nom}` insère une variable : `t('library.errors.folderNotFound', { path })`. Les nombres sont écrits selon la
langue (`1 234` en français, `1,234` en anglais). Une variable non fournie reste visible telle quelle (`{path}`),
pour qu'un oubli se remarque. Chaque langue emploie exactement les mêmes variables pour une clé.

## Pluriels

Un pluriel est un objet dont les clés sont les catégories d'`Intl.PluralRules` de la langue ; `other` est
obligatoire. La variable `count` choisit la forme.

- Français : `one` (0 et 1), `other` ; `many` existe pour les grands nombres ronds (un million), `other` suffit.
- Anglais : `one` (1), `other` (0, 2…).

Une forme absente se rabat sur `other`. Toutes les formes d'un pluriel emploient les mêmes variables (vérifié
sur l'ensemble des formes).

## Langue retenue et repli

- Réglage `ui.language` : `auto` (par défaut) suit les langues préférées du système
  (`app.getPreferredSystemLanguages()`) ; sinon un code BCP 47. Une valeur invalide redevient `auto`.
- Installations existantes : la migration v7 de la configuration (`src/main/config/migrations/v7.ts`) fixe
  `ui.language` à `fr` pour toute configuration d'une version antérieure, quelle qu'elle soit, et garde une langue
  déjà présente. Décision du 11/11/2026 : Mire n'existait qu'en français, une installation existante ne doit pas
  changer de langue d'elle-même. Une installation neuve, qui ne passe pas par les migrations, reste en `auto`.
- La langue retenue est toujours une langue disponible : code exact, puis même langue sans région (`fr-CA` → `fr`),
  puis variante régionale disponible (`pt` → `pt-BR`), sinon l'anglais.
- Un texte se cherche dans la langue retenue, puis en anglais, puis en français. Un texte vide compte comme absent.
- Une clé absente partout affiche la clé elle-même, jamais un texte vide ; en développement (application non
  empaquetée), elle est signalée dans la console du processus principal.

## Langue des fiches

Les fiches TMDB (`language`) et Steam (`l`, `cc`) sont demandées dans la langue de l'interface (`fr` → `fr-FR`,
`en` → `en-US`), sauf si `search.language` est fixé dans la configuration (`nl-BE`, `en-GB`…). Une valeur vide,
par défaut, suit l'interface (`src/main/i18n/metadata.ts`). La migration v8 de la configuration remplace `fr-FR`,
l'ancienne valeur par défaut, par une valeur vide : une installation existante, restée en français par la
migration v7, demande toujours ses fiches en `fr-FR`. Le pays des disponibilités (`search.region`) reste un réglage
à part.

Les fiches déjà récupérées gardent la langue dans laquelle elles l'ont été : changer de langue ne les traduit pas.

## Formats

Toujours par `Intl`, jamais à la main, avec la langue retenue : `formatDate`, `formatTime`, `formatNumber`,
`formatSize` (base 1024 : `1,5 Go`, `1.5 GB`), `formatDuration` (`1 h 5 min`, `1 hr 5 min`) et `compare` pour
le tri (numérique, sans tenir compte de la casse ni des accents).

## Ton des textes

Comme les textes français existants : simples, directs, sans jargon. La version anglaise garde le même ton ; elle n'est pas une
traduction mot à mot. Pas de majuscules de titre en anglais (`Download folder`, pas `Download Folder`).

## Dans le code

```ts
import { createI18n, BUILTIN_CATALOGS } from '@mire/shared/i18n';

const i18n = createI18n({ locale: 'fr', catalogs: BUILTIN_CATALOGS });
i18n.t('library.fileCount', { count: 3 }); // « 3 fichiers »
```

- Processus principal : le service de langue (`ctx.i18n` dans les handlers IPC) donne `t()` et le moteur de la
  langue retenue, et suit les changements de `ui.language`. Les textes produits loin des handlers (erreurs
  renvoyées à l'interface, boîtes de dialogue, boutique, genres) passent par `t()` de `src/main/i18n/current.ts` :
  la racine de composition y branche le service (`useLanguage`) ; sans service branché (tests), les textes sont en
  français. Un message est traduit au moment où il est produit : l'interface reçoit un texte prêt à afficher, pas
  un code d'erreur.
- Données qui ont des textes (boutique, genres) : elles ne portent que des identifiants, le texte est dans le
  catalogue (`store.emulators.<id>`, `store.bios.<id>`, `store.games.<id>`, `scrape.genres.games.<id>`,
  `scrape.genres.music.<id>`). Pour les genres, l'anglais reprend les valeurs des sources (libretro, MusicBrainz).
- Interface : `window.api.i18nGet()` rend la langue retenue, les langues disponibles et les catalogues à consulter
  (langue retenue, puis repli) ; `window.api.onLanguageChange(cb)` prévient d'un changement, à appliquer à chaud.
  L'interface s'en servira pendant la phase 2.

## Vérification

`test/i18n/main-hardcoded.test.ts` tient lieu de règle de lint (ESLint ne lit pas encore le TypeScript) : il
parcourt les chaînes de `src/main` avec le compilateur TypeScript et échoue sur un texte en français écrit en dur,
hors journaux de la console et exceptions listées (erreurs de programmation, réponses du protocole `media://`).
`test/i18n/main-language.test.ts` vérifie que chaque clé employée par le processus principal existe dans les deux
langues.

`npm run i18n:check` compare chaque catalogue de `locales/` au français : mêmes clés, mêmes variables, même forme
(texte ou pluriel), aucun texte vide, métadonnées complètes. Il sort en erreur et liste les problèmes ; la CI le
lance à chaque push. On peut lui donner un autre dossier (`node scripts/i18n-check.mjs <dossier>`), par exemple
pour vérifier un pack de langue.
